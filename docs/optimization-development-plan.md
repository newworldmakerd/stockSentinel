# StockSentinel 优化开发计划与验收条件

日期：2026-10-21。状态：实施中，逐项进度见[验收记录](optimization-progress.md)。本文不代表所有功能已实施，也不授权改库、重启或真实外部调用。

## 1. 背景与目标

先解决数据和连接故障可恢复、持仓成交可核对的问题，再用历史回放与盘中模拟验证策略增量价值，最后开展信号过滤、通知和模型治理。工程可用与策略有效分别验收，不能用测试通过或消息发送成功替代收益验证。

范围：行情可靠性、成交台账、企微恢复、可追溯回测、做T策略对照实验、费用流动性、通知冲突和模型预算。排除真实交易接入、自动下单、自动强制恢复底仓，以及未经验证直接替换线上策略。

已有 Java/Python 分工、群＋用户身份绑定、跨日可卖未知、人工收盘确认、完整K线、复权隔离和UNKNOWN不盲重发等规则保持。涉及这些规则变化，先单独提出并确认。

## 4. 工作包与可执行验收

### OPT-00：运行基线和共同测试底座（P0）

开发内容：建立逐来源、逐股票、逐扫描阶段的状态与耗时记录；明确数据获取、规则计算、通知排队、发送确认四种时间。保存原策略回归样例，整理模拟客户端和隔离数据库测试入口。

验收条件：

- 能区分“未到时间、未申报可卖、数据不足、数据过期、来源失败、规则未满足、已触发去重、排队、投递未知”，不得统称“没有信号”。
- 单条提醒能追到扫描任务、数据依据时间、规则版本和投递结果；没有数据的字段标缺失。
- 新增诊断不记录密钥、完整聊天原文或无关个人信息；公开状态不暴露用户持仓及群ID。
- 自动化测试只连本机模拟HTTP/WebSocket和隔离schema；不会因读取真实环境变量而向企微、模型或行情源发请求。
- 原日线、回踩推送时点、跨日可卖、人工收盘确认和UNKNOWN投递语义回归通过。

### OPT-01：做T历史数据可靠性与扫描预算（P0）

开发内容：先验证候选来源的5分钟历史、前复权、K线结束时间、覆盖长度和访问约束，再选后备；统一内部契约，增加限流、失败短时缓存、熔断恢复和逐扫描耗时预算。扩展现有异常提醒与状态接口。

验收条件：

- 来源能力验证形成可复核记录；若候选源不能提供一致历史及复权，不伪造后备，不用腾讯1分钟当前窗口拼成跨日RSI。
- 主源超时、5xx、空数据、乱序、重复、未来K线或过期时，分别有明确诊断；在预算内能尝试合格后备。
- 一次RSI计算使用同一来源、同一复权基准的完整窗口；主备切换不逐根混拼历史，不使用不复权价与前复权价拼接计算。
- 同一标准输入在主备适配器归一化后，RSI与独立算例误差不超过 `1e-8`；真实源存在差异时保留差异报告，不靠修改历史强行一致。
- 所有来源失败时禁止产生新的做T建议；仍可读取历史状态、执行不依赖行情的成交差额恢复检查。
- 同股多群多用户复用采集；成功请求每个5分钟槽不重复，失败请求受到单独退避限制，不能逐用户重试。
- 扫描预算可配置；故障模拟中不得无界等待或重叠扫描。预算耗尽明确标记，不能把未扫描股票记为无匹配。
- 建议连续3轮同类故障、15分钟冷却、恢复一次的既有提醒口径用于扩展；是否采用“仅做T故障”独立计数需确认。

### OPT-02：企微持续重连与连接故障展示（P0）

开发内容：瞬时连接故障采用有上限的指数退避和抖动，达到快速重试上限后改为冷却探测；保留凭据拒绝和被接管状态的人工处置边界。使用既有连接和队列，不新增同Bot并行连接。

验收条件：

- 本机WebSocket模拟连续失败超过10次后恢复，客户端可在下一冷却探测周期重新认证，不要求重启；冷却建议上限5分钟，待确认。
- 凭据被明确拒绝、连接被其他实例接管时不无限认证、不自动抢占；状态显示原因类别及所需人工动作。
- 断网期间积压消息不无限扩张；过期盘中消息不在重连后集中补发。
- 发送后失去ACK的消息保留UNKNOWN，不因连接恢复自动重发；重试不能承诺跨网络“绝对只投递一次”。
- 两群投递隔离且公平，不因某个群持续被拒绝阻塞另一个群。
- 连接故障可从本机状态页/接口或日志获知；不能只依赖已经断开的企微通道报警。

### OPT-03：可审计成交台账和仓位核对（P0）

开发内容：从每方向单次汇总升级为可追加成交事件，支持分笔、关联原事件的撤销/更正、数量和加权成交价重算。区分用户申报底仓、做T净增减、当日实际可卖与待核对差异；支持用户确认后的安全恢复观察。

验收条件：

- 先卖100股、再卖100股、回补50股后，累计卖200、买50、待恢复150；均价按数量加权，不按报价次数平均。
- 重复消息、并发重复请求不重复累计；更正与撤销保留原事件和操作者证据，不物理删除历史。
- 查询和写入继续按群＋回调用户＋股票隔离，模型不能指定其他人身份；否定、假设、问题或含糊成交指令不写入。
- 今日买入、历史可卖、已卖数量分别核对；不把新买股份自动认定为可卖，不把未申报成交推定为已执行。
- 没有资金总额或可用资金时，不编造买入额度或股数；仓位申报和成交台账存在差异时暂停扩大敞口，并说明差异。
- 中途更新仓位不静默丢失当日成交；按“暂停→展示差异→用户确认基准→恢复”的流程处理，恢复不重置当天通知去重或隐瞒风险。
- 14:50基于有效事件净额计算恢复差额；回补完毕后旧待发恢复消息失效。跨日未平衡敞口可查询，但不能用过期可卖数据自动开新观察。
- 是否允许晚间补录当日真实成交、分批恢复提醒，先确认后实现，不能默认沿用当前10:00—15:00写入限制或擅自取消。

### OPT-04：历史回放与盘中模拟账本（P1）

开发内容：复用Java规则和Python指标接口，建立确定性回放、模拟成交和持有底仓对照。回放与真实出站队列完全隔离；记录信号、假设成交与用户申报真实成交的不同来源。

工程验收条件：

- 同一冻结数据、参数、版本重复回放，信号与账本一致；中断恢复和一次完成结果一致。
- 任意时点只读取当时已完成且已可获取的K线；不能按产生信号的收盘价无条件假设已成交。
- 模拟包含费用、最低佣金、滑点、资金/可卖约束、停牌或无成交、涨跌停导致不可成交等情形；数据不足时不默认成交。
- 前复权研究数据与实际成交价格、持仓估值有明确换算依据；不得混用后计算收益。
- 真实推送不受模拟结果影响；一次回放不能给真实群新增关注、改仓或发送消息。
- 报告输出：与持有底仓相比的净增量收益、最大回撤、胜率、盈亏比、成交率、恢复失败比例、峰值临时敞口、被动留仓和卖飞机会成本；分别标明模拟和真实申报数据。

策略效果验收条件：

- 训练/调参、验证、最终样本外区间事先冻结；不得因回测结果不好反复重选最终样本区间。
- 包含不同流动性和趋势状态，不仅挑四川美丰或已知匹配股票；覆盖不足明确结论范围。
- 建议样本外覆盖至少60个交易日且至少100个闭合做T周期；不满足则结论为“样本不足”，不能宣布有效。该门槛是研究建议，不是统计有效性保证。
- 工程验收允许结果为亏损。是否达到上线标准，必须依据事先确认的风险上限、净增量收益要求和交易成本压力测试独立判断；未达标继续影子运行或停用，不强行上线。

### OPT-05：策略版本与输入证据（P1，与04最小闭环同时完成）

开发内容：每次评估记录策略ID/版本、参数快照、来源与数据版本、指标值、判定和跳过原因；支持只读解释和复现。明确历史复权重新计算时的数据版本。

验收条件：

- 从任意提醒可回答“当时用哪个版本、哪些数据、为什么触发、为什么没有触发”；缺失条件明确未评估。
- 修改参数产生新版本，不覆盖旧快照；旧提醒仍按旧版本解释。
- 规则输入快照或可验证的数据版本可重建结果，不能只保存当前重新拉取的前复权数据并宣称复现了当时结果。
- 用户消息与模型输出不能直接运行Java/Python、SQL或任意URL；后续自然语言策略仅允许受控表达式、校验、模拟、审批启用，本文不实现任意代码插件。

### OPT-06：RSI转折确认对照策略（P1）

开发内容：保留现有RSI极值策略为V1基准；研究V2“极值入观察→退出极值或价格转折确认→提醒”，并单独评估趋势、成交量或VWAP过滤的作用。各过滤项独立实验，不一口气堆全部指标。

验收条件：

- V1规则、阈值和线上行为不变；V2新版本默认仅影子运行，不额外给群发买卖建议。
- 在相同数据、成本和模拟成交假设下，对比信号数量、费用后增量收益、卖飞、回补失败和回撤；保存V2减少机会或恶化结果的案例。
- 转折确认只使用已完成K线；新条件、阈值、确认有效期和失效规则经确认并版本化，不能由模型现场更改。
- 不以胜率单项决定升级，不因过滤后信号更少就声称更优；通过04定义的样本外及风险门槛，获确认后才灰度切换。

### OPT-07：费用、波动空间和流动性过滤（P1）

开发内容：增加用户可配置费用模型、最小费用、滑点假设与流动性检查；使用成交台账计算已有减仓后的回补盈亏平衡价。对未成交周期，只显示估算情景，不声称知道未来回补价格。

验收条件：

- 买卖两侧费用分别按已确认口径计算，最低佣金、分笔、舍入及数量变化有独立算例；税费不从聊天中的模糊表述猜测。
- 提醒明确区分毛价差、估算成本、净价差/净金额以及实际成交结果；未知费用、资金或价格时显示未知，不输出伪精确净收益。
- 波动空间不足以覆盖建议成本缓冲时，可在影子版本中记录“空间不足”；阈值待回测确认，不能直接沿用固定0.30%作为所有账户真实成本。
- 流动性数据缺失、来源过期或无成交时，不作为“流动性正常”；无盘口数据时不编造买卖价差。
- 成本翻倍、滑点提高、成交延迟的压力测试可复现；效果不达标时不启用过滤版策略。

### OPT-08：策略冲突、个人提醒与日报展示（P2）

开发内容：在通知中区分周期、个人/公共范围、风险等级、触发与失效依据；同一股票集中展示近期事件，低优先级候选汇总，个人风险提醒优先排队。优化群助手状态查询和日报中的“为何没提醒”。

验收条件：

- “日线买入观察＋分钟减仓观察”能同时保留，解释持有周期不同，不由模型删改任何规则信号。
- 个人止损、公共风险、做T观察和候选推荐的显示优先级事先确认；队列拥塞时优先投递风险消息，低优先级合并不吞风险事件。
- 同一提醒重试不生成新事件；早晚回踩候选仍按用户要求允许重复，不被新增全局去重误伤。
- 过期数据、未扫描、无匹配和通知失败分别展示；日报有数据依据日、覆盖率及异常类型，不将累计历史异常全部描述成当前故障。
- 消息满足现有4000字节限制，按UTF-8字节验证；表格在实际企微客户端的兼容性单独验收，不支持时降级成可读列表。
- 真正@所有人的协议支持与权限单独核验；未确认能力前不以文字“@所有人”宣称已提醒全员。

### OPT-09：模型预算、缓存和超时降级（P2）

开发内容：记录按模型、调用目的和群维度的请求量、实际usage、估算费用；建立日预算、工具调用上限和解释缓存。预算或服务异常时保留规则链路。

验收条件：

- 每分钟行情扫描、RSI计算和本地风险判断不调用模型；群问答、意图识别和规则后解释分别计量，不能只统计其中一种调用。
- 同一信号、版本、数据和模型配置复用解释；不同用户私人仓位不能互相命中缓存。
- 并发请求接近预算上限时先原子预留，完成后按真实usage结算；供应商未返回usage时标明估算，不能伪称精确账单。
- 达到预算上限后不再发起新增模型请求；已在途请求的预留和失败结算有确定规则。规则信号、个人风险和投递继续运行。
- 模型超时、429、无效工具参数或不可用时给出可理解降级结果，不能宣称未完成的写操作成功，也不能编造行情或交易建议。
- 预算金额、按群是否独立、管理员权限和隐私可见范围需先确认；密钥仍只在环境变量中。

## 5. 开发顺序和交付要求

1. OPT-00建立现状基线与回归样例。
2. OPT-01、02分别交付；只改变可靠性，保留现有策略参数。
3. OPT-03完成真实申报成交闭环，同时完成OPT-05最小输入快照。
4. OPT-04建立回放和模拟账本；补齐OPT-05历史复现能力。
5. OPT-06、07独立影子实验；未达到策略验收门槛不切线上。

```sql
-- 分阶段查找近期失败，不把空结果当成策略正常。
SELECT j.id, j.trade_date, i.symbol, i.stage, i.status, i.code
FROM job_execution j
JOIN job_execution_item i ON i.job_id = j.id
WHERE j.trade_date = DATE '2026-10-21'
  AND j.job_name = 'INTRADAY_SCAN'
  AND i.status IN ('FAILED', 'SKIPPED')
ORDER BY i.id DESC
LIMIT 100;

-- 仅统计投递状态，不输出群ID、个人身份或消息正文。
SELECT message_type, status, COUNT(*) AS total
FROM notify_record
WHERE created_at >= TIMESTAMPTZ '2026-10-21 00:00:00+08'
  AND created_at <  TIMESTAMPTZ '2026-10-22 00:00:00+08'
GROUP BY message_type, status
ORDER BY message_type, status;
```

## 8. 风险、灰度和回滚

- 新模块独立开关、先模拟再影子，再按配置群或股票灰度；灰度是新增策略版本的范围限制，不擅自改变现有共享关注语义。
- 数据后备若不一致，禁用该后备并展示降级；不通过放宽新鲜度或使用未完成K线掩盖故障。
- 新迁移只追加；旧台账迁移前做可恢复备份和数量/金额对账，原汇总记录标明历史来源，不能捏造分笔时间。
- 关闭模块只停止新评估/新入队，不抹去已发生的成交或敞口；仍需允许只读核对及人工风险处理。
- 有状态迁移后的回滚必须验证旧程序兼容；不直接回滚数据库版本或删除新表，不以重发UNKNOWN恢复通知。
- 人工闭环仍依赖用户真实申报；系统无法保证收盘平仓、盈利或消息必达。未完成真实盘中验收时，验收记录明确标记，不用模拟结果代替。
