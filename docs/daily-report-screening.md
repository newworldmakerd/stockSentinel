# 交易日日报与全市场技术观察候选

2026-10-20 用户确认：交易日 15:30 推送至既有企微群；包含关注股当日涨跌、规则信号、扫描及行情异常，并追加大盘与技术关注候选。用户进一步明确要求先发送一份查看效果。

## 已实现流程

- 独立调度线程，每分钟检查已导入 CN 开市日历。09:35 起在独立后台线程启动全市场技术扫描，重启后可恢复未完成的 PENDING 项；不会占用分钟监控线程。
- 15:25 异步刷新上证指数、深证成指、创业板指及沪深个股报价；15:30 起生成日报。进程错过时间时，在同日 23:00 前补发一次；周末、休市或缺日历不发。
- 每个交易日、机器人与目标群唯一一份，内容生成后固定。发送持久化，数据库原子认领与令牌防并发；明确临时错误最多三次，UNKNOWN 不自动重发，失联超时认领标记 UNKNOWN。
- 报价由 Python 从腾讯按每批至多100个代码获取，批次间至少1秒，包含实际行情时间和失败代码。Java 存储快照、计算涨跌和市场宽度、汇总信号与任务；Python 不连接业务数据库。
- 日报展示最多8只启用关注股、最多5只技术候选，超过4000字节限制前按完整字符截短，并提示查看 API；不会拆成多条刷屏。

## 技术候选口径

范围为本地股票目录中 ACTIVE 沪深 A 股，按当前报价名称排除 ST、当日报价缺失及无成交股票。至少121条完成日线，为120日指标预热与前后两日比较提供数据，也排除上市历史不足的股票。行情或历史证明不足则跳过，不猜测上市日期、停牌状态或成交额。

流动性：最新20条 NONE 日线成交额必须全部存在，平均人民币成交额至少1亿元。

复用 `SWING_TREND_V1` 的 BUY_WATCH 规则与版本参数：MACD 金叉、价格严格高于 MA20、MA20 严格向上、成交量满足前5日均量倍数。使用原 Python 指标服务和 Java 规则引擎，未另造评分或更改原策略。策略禁用时不生成候选。

候选持久化后，仅对按20日平均成交额降序、代码升序排列的前5只调用模型解释。解释缺失时标明未生成；模型不改变是否入选、排名或参数。候选不写成实时规则推送、不自动加入关注、不执行交易。

生成日报时还按收盘时段报价再次检查候选是否有当前交易日成交、是否ST。报价不足时不强行推荐，显示不足原因。技术候选不代表盈利、估值或基本面优质。

## 数据日期与覆盖边界

原“当日日线需人工确认”的规则保持。未人工确认当日时，筛选使用上一已导入开市日；已确认时仍经过既有逐来源确认校验。日报始终注明技术依据日期，当日涨跌则使用带真实时间戳的当日报价。

全市场初次历史采集可能较长，且依赖东方财富日线可达性。连续10次历史或计算错误会停止本日扫描，保留 SOURCE_UNAVAILABLE 与未处理项，避免不断请求失败供应商。其他逐股失败也持久化。覆盖数、失败数、PENDING 和任务状态会原样展示，不能把未扫完解释成“全市场没有机会”。

每日09:35启动是为了给历史采集留时间；不能保证所有股票都能在15:30之前完成。当天日报只发一次，后续扫描完成不会自动补发第二份；最新完整结果可通过筛选 API 查看。目录维护仍沿用股票同步接口，目录缺失或过时会影响范围，需要维护。

## API

| 方法与路径 | 行为 |
|---|---|
| GET /api/v1/reports/daily/preview?tradeDate=2026-10-20 | 只读生成预览，不发送、不获取外部数据 |
| POST /api/v1/reports/daily | 当日收盘后的开市日报入队；重复返回同一条记录 |
| GET /api/v1/reports/daily?tradeDate=2026-10-20 | 已保存日报、状态与次数；不返回目标群或凭据 |
| POST /api/v1/screening/scan | 异步启动当日扫描；已在运行或已结束时不重复启动 |
| GET /api/v1/screening?tradeDate=2026-10-20 | 数据日期、状态、股票池、逐状态数量与前5候选 |

不自动重跑当天已终止的全市场任务，次日生成新的独立任务。多个实例使用 PostgreSQL advisory lock(76301,3) 防止同时全市场扫描。信号、分钟与日线的原互斥锁不变。
