# StockSentinel 优化建议（2026-10-21）

## 1. 背景与目标

建议先改善扫描可靠性、全市场数据覆盖和收盘任务补跑，再扩展策略。当前已经具有行情、规则、模型解释、群交互和个人提醒链路，但策略初始参数尚未通过回测验证。本次只读检查并新增此建议文档，不修改业务代码、配置或运行中的任务。

## 3. 建议方案

### 第一批：可靠性和完整覆盖

1. **细分失败原因与数据新鲜度。** 给行情获取、分钟校验、规则计算、持久化分别记录安全错误码与耗时；展示来源、行情时间、连续失败次数。只记录脱敏摘要，不保存凭据、完整模型请求或原始群消息。先定位上述失败样本，再决定是否调整接口、超时或重试。
2. **分钟任务优先，全市场扫描限速。** 保留已有断点续扫与缓存；评估将批量历史获取与分钟获取分离到有界队列或独立资源。历史增量更新必须处理前复权历史修订、来源切换和指标预热窗口，不能简单只追加最新一行。不要直接增加线程数冲击上游。
3. **人工确认后补跑日线。** 保留人工收盘确认，增加确认成功后的幂等触发与有限时间补偿。按交易日和任务类型防重，显式记录触发人和依据；不能以时间到了替代收盘确认。

下面的只读 SQL 可复核失败类型；属于诊断片段，不包含数据修改：

```sql
WITH recent AS (
    SELECT id FROM job_execution
    WHERE job_name = 'INTRADAY_SCAN'
    ORDER BY started_at DESC LIMIT 20
)
SELECT i.code, count(*)
FROM job_execution_item i JOIN recent r ON r.id = i.job_id
GROUP BY i.code ORDER BY count(*) DESC;

SELECT status, count(*) FROM notify_record GROUP BY status;
SELECT status, count(*) FROM signal_advice GROUP BY status;
```

### 第二批：提醒更清楚、策略可验证

4. **保留重复推荐，增加状态变化说明。** 遵循当前需求继续每 10 分钟推荐重复候选；标记“首次入池 / 持续观察 / 已转强 / 条件失效”，展示入池时刻、距突破价幅度及最新数据时间。同一发送时段的投递防重仍保留。
5. **个人提醒操作回执与查询。** 设置成功后回读本人、股票名称代码、止盈止损价格、触发基准、有效状态；对话中途失败时分别说明实际已完成的操作，并引导查询个人提醒。继续发在本群并标注所属用户。先改善价格提醒，持仓成本、百分比或移动止损另行定义，不能推测用户成本。
6. **策略回放和效果复盘。** 优先验证缩量回踩及卖出/风险规则，记录信号后不同窗口表现、回撤、触发频度和漏数情况。历史样本必须处理复权、停牌、涨跌停、T+1 和交易成本，避免未来数据泄漏；验证结果不能当成收益保证。先比较既有参数，再讨论调参。
7. **运行可见性与本机恢复。** 增加只读运行页或群状态摘要，集中展示扫描覆盖、最新分钟、失败原因、模型状态和投递未知状态。后续可增加 Windows 开机启动及进程恢复，继续采用本机运行方式；部署操作需单独确认执行。

第二批是候选需求，尚未确定接口和数据库契约，因此本次不提供可能误导为可直接上线的实现代码；选定范围后再形成具体迁移、实现和测试方案。

## 4. 必须保留的拦截与边界

- 交易日、交易时段、完整分钟、行情时效和日线人工收盘确认校验继续生效。
- Java 负责规则、写库与通知，Python 不连接业务库；复权和不复权数据不得混算。
- 模型解释在本地规则信号之后产生，模型失败不得篡改规则；群助手只通过已校验工具操作。
- 个人提醒继续按群和真实回调用户隔离，不能由文本中的昵称或模型参数冒认用户。
- 重复候选推荐与通知投递幂等是两个层面；不能为恢复重复推荐而删除发送防重。
- UNKNOWN 投递不能直接自动重发；保留现有重试、过期和取消边界。
- 不自动下单，不自动加入推荐股票，不修改已执行 Flyway 迁移。

## 5. 待确认的需求选择

建议按“失败定位与可观测性 → 行情资源隔离和覆盖提速 → 收盘确认补跑”实施。后续需分别确定：群故障摘要的接收范围和频率、人工确认的权限及补跑截止时间、个人提醒是否需要持仓成本及百分比规则、回放样本区间和评价指标。此处仅列后续设计问题，本次不请求运行或变更授权。

## 6. 验证方式、回滚与风险

- 用模拟行情、模型和企微客户端验证超时、数据过期、局部失败、未知回执；自动测试不调用真实服务。
- 比较调整前后分钟任务延迟、逐股失败率、全市场覆盖进度，避免只看吞吐量。
- 对确认后补跑验证未确认不执行、重复确认不重复计算、跨日不误跑。
- 对会话回执验证个人写入完成后模型失败的提示，并验证不同用户不能修改他人提醒。
- 每项独立交付，保留开关；有数据库变更时新增 Flyway 迁移，不能修改历史迁移。回滚优先关闭新路径，避免撤销已产生的提醒或删除审计记录。
- 本次未修改业务代码，因此不执行编译测试、不重启服务、不触发真实行情、模型或群推送。
