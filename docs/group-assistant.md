# 企微群对话助手与关注人

## 使用方式

在配置的企微群里@机器人，可以说：

- “看看本群关注了哪些股票，分别是谁关注的？”
- “我的关注列表”“继续看后20只”。
- “亨通光电是谁关注的？”（读取本群列表定位；超过20只时分页）
- “解释缩量回踩策略”“现在卖出规则开启了吗？”
- “亨通光电最近有哪些信号？”“当前扫描到哪里了？”
- “监控四川美丰”——只支持本条明确新增一只股票，保留已有监控阈值。
- “叫我小刘”——设置本群内自己的显示名称，之后关注列表同时显示企微用户ID和显示名。此名称是用户自设，不是企业通讯录核验结果。

多人关注相同股票会各自记录，底层共用一份监控，不覆盖彼此。历史关注及本地API添加的公共关注没有可信关注人，显示“来源未记录”，不把历史股票强行归给某个人。个人列表仅包含上线后显式登记的本人关注；历史股票可通过明确关注命令登记本人关注关系。

## 工具契约

模型采用现有DeepSeek兼容接口和受控function calling。工具实际执行逻辑在`GroupAssistantTools.java`，字段严格校验；用户和群身份来自智能机器人回调，模型不能指定userid、chatid、URL、SQL或执行方法。

| 工具 | 输入 | 行为 |
|---|---|---|
| list_watchlist | scope=mine/group，offset可选 | 20只一页，返回中文名/代码、监控参数、关注人；单股关注人最多20人 |
| get_strategy_info | 空对象 | 读取策略参数、盘中条件、缩量回踩参数和开关 |
| get_monitoring_status | 空对象 | 读取交易日历、扫描进度和前5只回踩候选；不取实时行情 |
| get_recent_signals | stock_query可选 | 最近5个自然日已落库信号，最多10条；不重新生成信号或建议 |
| search_stocks | query | 本地股票目录，最多10个结果 |
| add_stock_monitor | stock_query | 本条原文须明确新增单只股票；复用原意图校验及订阅服务，在同事务记录关注人 |
| set_my_name | name | 本条明确“我叫/叫我/昵称”且名称逐字出现，最多40字符，只改自己 |
| set_personal_price_alert | stock_query、take_profit/stop_loss至少一项 | 明确本条个人价位，不覆盖公共或别人；详见[个人提醒](personal-price-alerts.md) |
| list_my_price_alerts | stock_query/offset可选 | 查询本人止盈止损提醒 |
| disable_personal_price_alert | stock_query | 明确关闭本人该股的个人价位提醒 |

每条消息最多执行一次写操作；多工具调用最多8次、最多5轮模型请求，每轮HTTP超时20秒。新增关注另复用原意图识别超时。参数越权、未唯一匹配或不支持的工具返回错误，不执行SQL或下单。查询与解释不新增关注、不改变策略，不开放删除关注、交易、任意HTTP、文件或Shell工具。

## 对话与权限范围

只处理已有配置的Bot和群回调，保留旧消息去重、过期检查、自消息忽略、有界队列及异步处理。配置`WECOM_CHAT_ASSISTANT_ENABLED=true`后开启通用群对话；默认false时保留原单股票监控指令行为。它仍依赖`WECOM_COMMANDS_ENABLED=true`及企微开关。用户在群里@机器人后收到回调，采用原长连接发送回复。

聊天上下文仅在内存中按群+企微用户ID隔离，最多100位用户，每人最近6轮，20分钟未活动过期，重启清空。不保存或记录聊天原文、模型回复、凭据。V7继续仅存回调摘要和状态。新V12保存关注关系和自设昵称，属于用户明确要求的归属信息；未回填历史归属。关注关系以群摘要+userid+股票代码唯一，幂等记录。

这是一套共用本机监控，当前开放配置白名单内的多个群，回复回到来源群，配置方式见[多群支持](multi-chat.md)。群列表含本地API添加的公共关注，不能视为多租户隔离系统。群内关注人为企微回调userid；机器人没有通讯录权限，不会擅自查询通讯录。

交易分析仍先有本地规则信号再调用模型。新增通用对话是用户明确追加的独立入口，允许解释策略、查询数据与工具操作；不得凭空生成当前行情、持仓或买卖结论。超时可能发生在写操作成功之后，回复会提示核实，重复回调不会自动重做。

## 开关、API与测试

`.env.example`新增`WECOM_CHAT_ASSISTANT_ENABLED`，本机授权启动脚本设为true。密钥继续来自环境变量。`GET /api/v1/monitoring/status`增加`chatAssistantEnabled`，不返回用户、群目标、密钥或聊天内容。新工具不增加外部业务写API；新增关注复用`MonitorSubscriptionService`的校验，在事务内追加关注人，原本地API契约保持。

测试通过本机HTTP假模型验证实际工具轮次和tool结果回传，原群指令与新对话在隔离schema里验证。覆盖多用户归属、历史未知、重放幂等、只读不写入、禁止伪造身份、别名只改本人、不支持股票整笔回滚、跨群拒绝及上下文隔离/过期。测试不调用真实行情、模型或企微。
